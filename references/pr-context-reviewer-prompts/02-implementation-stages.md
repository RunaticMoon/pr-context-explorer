# 단계별 후속 개발 프롬프트

마스터 프롬프트의 모든 기능을 한 번에 다시 전달하기보다, 현재 단계의 지시를 추가해 작업 범위를 고정한다. 모든 단계는 `01-project-master.md`의 보안·근거·revision 규칙을 유지한다.

## 1단계 — 설계와 클릭 가능한 전체 경험

```text
01-project-master.md를 제품 요구사항으로 사용하라. 현재 코드와 환경을 확인한 뒤 최소 실행 가능한 전체 사용자 경험을 구현하라.

이번 단계의 범위:
- 제품 요구사항, 아키텍처, 출력 계약, 보안 경계, 작업 계획을 docs에 작성한다.
- 실제 GitHub/AI 계정 없이 실행할 수 있는 명확한 데모 모드를 만든다.
- Jira 1개, 실제로 생성한 작은 fixture Git 저장소의 커밋 3개, 파일 6개 이상을 사용한다. SHA/라인/diff를 손으로 조작한 가짜 Git 사실로 만들지 않는다.
- 예제 변화는 입력 규칙 추가 → 핵심 처리 연결 → 테스트 보강으로 하되 파일명 순서와 추천 읽기 순서가 달라야 한다.
- PR 목록 → PR 작업공간 → Phase 그래프 → Guided Flow → 코드 설명 이동을 구현한다.
- 실제 정적 관계를 검증할 수 있는 fixture를 만들고, 고정된 예제 설명은 MockProvider 결과임을 표시한다.
- 세 모드의 공통 선택 상태와 EvidenceRef 탐색을 먼저 완성한다.
- Phase 변경 시 해당 SHA의 파일 상태가 바뀌는 테스트를 만든다.

외부 연동을 했다고 주장하지 말라. 설치/실행 방법, 수정 파일, 수행한 테스트, 모의 처리 부분을 보고하라.
```

## 2단계 — 실제 GitHub / Enterprise와 Git 이력

```text
마스터 요구사항과 현재 구현을 읽고 실제 읽기 전용 GitHub/GHES 연동을 구현하라.

내 작성 PR 목록, 검색/페이지네이션, PR URL 입력, 호스트별 인증 사용자 확인, PR 원문·모든 커밋·변경 파일 수집을 연결한다. API base URL과 버전은 배포 유형별로 설정하고 인증정보를 다른 호스트로 전달하지 않는다.

앱 전용 캐시에 선택한 PR의 Git 객체를 안전하게 확보한다. base/head/merge-base와 수집 범위를 고정한 snapshot을 만들고 커밋별 실제 tree 및 부모 비교 diff를 추출한다. 전체 PR diff와 커밋별 diff를 구분한다. 사용자 작업 트리는 건드리지 않는다.

API 상한, 누락 patch, fork PR, 비선형 이력, merge, rename/delete, 최종 상태에서 되돌려진 변경을 테스트하라. API로 모두 받지 못했으면 명시적 보완 또는 partial 상태로 처리한다.

통합 테스트는 인증 없는 fixture와 mock HTTP로 재현 가능하게 만들고, 실제 계정 확인은 별도 opt-in smoke test로 둔다. 실계정 접근을 수행하지 못했으면 테스트했다고 보고하지 않는다.
```

## 3단계 — Jira와 로컬 AI 엔진

```text
현재 snapshot/근거 계약을 유지한 채 Jira 연결과 CodexProvider, ClaudeCodeProvider를 구현하라.

Jira 연결:
- PR/브랜치/커밋에서 후보를 추출하고 출처를 기록한다.
- 호스트별 키 매핑, 명시적 링크 검증, 중복 제거, 수동 연결을 구현한다.
- 선택한 Cloud 또는 Data Center 어댑터에서 제목/본문/설정된 수용 기준 필드를 읽는다.
- 원문 정규화와 fetchedAt/updatedAt/해시를 보존한다.
- 미연결/읽기 실패에도 PR 분석이 가능하게 한다.

AI 연결:
- 설치된 CLI 버전, 인증 방식, 비대화형 실행과 구조화 출력 지원을 확인한다.
- 읽기 전용 ContextBundle을 입력으로 하고 GitHub/Jira 자격증명은 실행기에 넘기지 않는다.
- 공통 시스템 프롬프트 + 작업별 런타임 프롬프트 + 실제 JSON Schema를 적용한다.
- 모델 출력과 CLI 이벤트 envelope를 분리한다.
- 제한된 도구, 자동 로드 설정 통제, timeout/cancel, 크기 제한, 오류 처리를 구현한다.
- 스키마 및 evidenceIds 검증이 끝난 결과만 성공으로 저장한다.

두 엔진 모두 어댑터/파서/오류 계약 테스트를 작성한다. 미설치 엔진의 실제 동작이나 사내 서비스 호환성을 검증했다고 주장하지 않는다. MockProvider와 실제 결과는 UI에서 항상 구분한다.
```

## 4단계 — 맥락 중심 그래프·투어·코드 설명

```text
현재 실제 수집 및 분석 파이프라인 위에 핵심 UX를 완성하라.

Graph:
- 파일 ID와 커밋별 path/blob 상태를 분리한다.
- Phase별 실제 상태, 변화 배지, 안정적 배치, 문맥 노드 확장, 근거 선택을 구현한다.
- 정적 코드 관계, AI 추정 관계, 추천 읽기 순서의 선을 별개로 관리한다.

Guided Flow:
- 커밋 순서가 아닌 이해 순서를 생성한다.
- 각 단계에 읽는 이유, 이전 단계와 연결, 핵심 코드 구간, Jira 근거, 확인 질문, 다음 단계 이유를 넣는다.
- 읽음 상태와 이어보기를 snapshot별로 보존한다.

Code Explorer:
- 파일/함수/선택 구간의 역할, 입력/출력, 변경 전후, 호출 및 데이터 흐름, 오류 처리, 검증 포인트를 설명한다.
- on-demand 분석과 캐시를 사용하고 모드 전환만으로 AI를 재호출하지 않는다.

단계 이동, Phase 이동, 파일 클릭, 모드 전환, 브라우저 뒤로 가기에 대해 snapshot/commit/file/range가 일치하는 E2E 테스트를 작성한다. 설명은 반드시 같은 revision의 코드에 연결되어야 한다.
```

## 5단계 — 신뢰성·보안·완료 검증

```text
새 기능을 늘리지 말고 마스터 프롬프트의 완료 조건을 하나씩 검증하라.

필수 검증:
- PR/Jira 원문과 실제 코드가 서로 다른 경우 불일치 표시.
- AI가 존재하지 않는 SHA·파일·라인·근거를 반환하는 경우 거부 또는 격리.
- 근거는 유효하지만 주장과 관련이 없는 경우 의미적 점검 실패 표시.
- merge/fork/rename/delete/revert/force-push/shallow/binary/대형 PR/미지원 언어.
- Jira 401/403/404, GitHub 목록 제한, 부분 응답, 엔진 미설치/만료/취소/비정상 출력.
- PR 본문만 수정, Jira 내용만 수정, 모델/프롬프트/파서 버전 변경 시 캐시 갱신.
- 악의적인 PR/Jira 문구, 대상 AGENTS.md/CLAUDE.md, hook/MCP 자동 로드, symlink와 경로 순회, shell 인젝션, XSS, 외부 이미지, 로컬 API에 대한 외부 Origin 접근.
- 원격 GitHub/Jira 쓰기 요청이 발생하지 않고 사용자 작업 트리가 변하지 않았음.

성능은 환경과 fixture 규모를 기록하고 실제 측정값만 보고한다. fixture 검증과 실제 사용자 계정 검증을 분리한다. 설치, 연결, 사내 CA/프록시 설정, CLI 문제 해결, 캐시 삭제, 알려진 한계를 문서화하라.

끝으로 완료/부분완료/미검증 표를 제출하라. 테스트하지 않은 항목을 완료 처리하지 않는다.
```
