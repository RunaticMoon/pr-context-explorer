# Public binary distribution and in-app updates

## Authorization and repositories

One public repository: `RunaticMoon/pr-context-explorer` (source and releases together; no separate release repository). Publication uses the workflow's own `GITHUB_TOKEN`, injected as `GH_TOKEN` only in the publisher step of the `public-release` environment; it is never an app setting or artifact. The app's anonymous update feed points at this same public repository.

The `public-release` environment deployment branches are restricted to `main`; the exact branch rule was read back. No required-reviewer or wait-timer protection is claimed (the account rejected a wait-timer setting). Explicit reviewed-SHA workflow dispatch, independent CI gates, and the trusted repository operator remain the publication authorization boundary.

## Release contract v1

Asset `public-mac.json` has exactly:

```json
{"schemaVersion":1,"channel":"public-personal-unsigned","repository":"RunaticMoon/pr-context-explorer","version":"0.6.1","tag":"v0.6.1","sourceCommit":"<40 lowercase hex>","platform":"darwin","arch":"arm64","asset":{"name":"PR-Context-Explorer-0.6.1-arm64.zip","size":123,"sha256":"<64 lowercase hex>"}}
```

Example size/hash are placeholders in documentation only. Generate real metadata from the verified signed/ad-hoc final ZIP. A public release contains ZIP, DMG and this manifest; no test logs or publisher credentials. GitHub's autogenerated source archive contains the tested source tree at the tagged commit. The public tag points at the exact tested source commit, so `sourceCommit` equals the tag commit. Explicitly trust GitHub HTTPS and authorized repository publishers; hashes do not protect against compromise of both artifact and manifest.

## Client boundaries

- Fixed repository, unauthenticated HTTPS, no PAT, gh or end-user Python. Never reuse PR/Jira credentials. Bound API/download time, body size, redirects and progress. Validate each redirect destination and TLS; never disable certificate checks.
- Stable newer semantic versions only; no downgrade, prerelease/draft or cross-channel fallback. Exact release/tag/asset name/size/hash agreement, strict schema and resource ceilings.
- Validate ZIP paths, case collisions, links and sizes before extraction. Verify real arm64 app identity/version, dependency inventory and code signature before replacement. Ad-hoc integrity is not Apple identity/notarization.
- Existing source/private updater remains separate. Public updater is the personal-build default once shipped; optional signed channel must not silently consume unsigned metadata.
- Automatic check on startup and bounded periodic intervals. Download automation is explicit opt-in. Native confirmation for update-and-restart; active analysis prevents replacement. No privileged escalation, shell injection, quarantine removal, or global security changes.
- Dedicated helper uses only bundled Node and app-owned code, staged outside the bundle before replacement. Current app path originates in main process, never renderer/manifest. Wait for exact old-process exit, lock, same-volume staging, revalidate, swap with backup and rollback on validated failure. Preserve Application Support data. Document crash/power-loss and permission/Gatekeeper limits.

## Implementation ownership and integration

1. Core agent: `desktop/public-update/**` and its tests. Owns transport, strict manifest, staging/install worker and status controller; publishes a concrete Node-only API for Electron integration. No version/CI/root edits.
2. Desktop agent: main/preload/preferences, build/package integration, settings Updates UI, lifecycle admission/busy handling and isolated Mac tests. Coordinate only through core's documented module contract; no arbitrary IPC URL/path/command parameters.
3. Release agent: public manifest generator, public publisher and gated workflow. Build/test on Mac15, install exact ZIP on Mac26, then publish using the workflow token only. Read back/download/compare assets before undrafting. No overwrites/reuse of published tags.

Parent integrates dependencies/version, audits output, performs tests and actual Mac verification, and publishes only after all gates pass. First public-updater DMG must be installed manually once; older versions cannot discover this new channel. PR/Jira authentication is unaffected. Actual user-machine update behavior and Gatekeeper approval are distinct from CI verification.
