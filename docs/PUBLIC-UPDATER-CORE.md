# Public updater core (integration contract)

**Dependency needed by parent now:** exact production dependency `yauzl: "3.4.0"`. Bundle it into both main and the standalone Node helper with esbuild; no runtime npm or host node_modules lookup. npm registry version/integrity verified; upstream https://github.com/thejoshwolfe/yauzl and npm identify 3.4.0 (security listing reports no known direct issue). Local implementation tests use an isolated `/tmp/prce-public-update-deps` install, not root package edits.

Main entry: `desktop/public-update/index.ts`, exports `PublicUpdater`.
Trusted-main constructor options: `{ currentVersion, appPath, dataDir, nodePath, helperPath, isBusy: () => boolean, onStatus?: (status) => void }`. No renderer-supplied URLs, paths, versions, hooks or commands. Service methods: `check()`, `download()`, `cancel()`, `prepareInstall()`, `close()`, and `status` getter. `prepareInstall()` resolves only after detached helper acknowledges ready; then main should quit, after its lifecycle admission lock prevents new analysis. It throws BUSY if work is active. Main must hold that admission lock until quit or failure, not merely sample busy once.

Status: `{ phase: 'idle'|'checking'|'available'|'current'|'downloading'|'downloaded'|'preparing'|'ready'|'cancelled'|'error', version?: string, received?: number, total?: number, errorCode?: string }`. Errors are fixed codes, not raw remote messages/URLs.

Helper build entry: `desktop/public-update/helper-entry.ts`; bundle platform=node format=cjs to `public-update-helper.cjs` as an extra resource. `helperPath` points there, `nodePath` points to `Contents/Resources/node/bin/node`; both copied outside installed bundle before spawning. Main startup must call exported `registerStartup(appPath, currentVersion)` **early, before admitting analysis**, then exported `acknowledgeStartup(appPath, currentVersion)` **only after runtime/server/window readiness**. `registerStartup` returns true only for an update-launched process. Keep analysis admission closed between registration and acknowledgement; helper may terminate only this new boot-identified process on startup failure. Do not allow user work until acknowledgement completes. These calls are harmless no-ops for normal launches (no updater argument). This writes a private receipt for the helper to verify. Parent must wire this explicitly or startup timeout causes rollback.

## Security and filesystem contract

- Production HTTPS sends no Authorization/cookie/provider headers, explicitly verifies certificates, pins the release API path and repository asset paths, rejects private/reserved DNS addresses, and permits only bounded GitHub-controlled asset redirects. It never consumes a renderer URL, PAT, `gh`, Python or provider settings. Internal `fetchBytes` transport injection exists only for code-level tests; `PublicUpdaterOptions` has no transport override.
- Listing is limited to five 100-release pages and 2 MB per page. A full fifth page fails rather than claiming completeness. Select the greatest strictly newer stable version, not API ordering; drafts/prereleases are excluded. Manifest is at most 16 KiB, exact keys/channel/tag/version/platform/arch/name/size/hash. Duplicate JSON keys and invalid UTF-8 are rejected. Metadata trust is authorized public-repository publishers over GitHub HTTPS, not independent cryptographic publisher attestation. `sourceCommit` is provenance, not the public tag commit.
- ZIP ceiling: 1.5 GB compressed, 4 GB expanded, 1 GB per file, 50,000 entries, bounded compression ratio, symlink content/chain bounds. Complete ZIP SHA-256 and byte size are checked before preflight/extraction. Traversal, absolute/backslash/colon/control paths, foreign roots, AppleDouble, case/normalization collisions, duplicate paths, encrypted/unsupported methods, special files, set-ID/sticky modes, local-header mismatches and overlapping entry extents fail closed. Only internal, non-dangling symlink graphs are created, after regular files; symlink parents are prohibited. CRC uses bundled Node's `zlib.crc32`.
- Download caches are under the supplied canonical existing private data directory. The service cleans its own random cache job on cancellation/close and after acknowledged handoff. No sweeping of unrelated/old directories. Work and backup directories are random owner-only siblings of the installed app; native Node, helper code, and the existing native ACL reader are copied outside the bundle before replacement. User/Application Support data is never part of the replacement transaction.
- Directory/file ownership, mode, link count, nofollow/exclusive opens and all ancestors are checked. On macOS, the existing signed/ad-hoc native ACL reader checks every accessed directory/file; only exact empty/deny-only responses are accepted. ACL metadata results are cached by inode/device/change-time/mode/owner/group. The helper's ACL reader is copied beside its standalone Node. Root-owned sticky temporary ancestors and exact stock `/Applications` root:admin(80), mode 0775 are narrow exceptions; root/authorized administrators and the same user are outside the hostile-party boundary. Other writable ancestors and ACL grants fail closed. No permission repair, privileged escalation or quarantine removal.
- The installed app must be owned by the current user and replaceable without privilege. Canonical main-owned app path must end in `PR Context Explorer.app`; the node/helper paths must match their fixed resource locations. Info.plist identity/version/executable, bounded actual ASAR package/version, arm64 Mach-O executables, complete runtime dependency inventory and within-runtime dependency closure, native helper libraries, and deep strict code-signature integrity are verified. Ad-hoc signing is integrity checking, not Apple Developer ID trust or notarization.

## Handoff and recovery

1. Native confirmation plus the host's lifecycle admission lock must precede `prepareInstall()`. Keep analysis admission closed while it runs and until quit. The service samples `isBusy()` before preparation and again after helper-ready; sampling alone is not an admission lock.
2. Service captures the exact current process UID/start-time/command identity, stages on the same volume, validates, creates a nonce plan, and starts copied bundled Node with a clean environment and IPC. A fixed `.prce-public-update.lock` excludes writers; the helper acknowledges the nonce only after its own plan/hash/app checks and acquiring the lock. Never quit on spawn success alone.
3. Helper waits for the exact old process to exit within the plan deadline. It never kills/signals the old process. Cancellation writes a private marker. PID identity change fails closed; stale locks are never automatically stolen.
4. Helper revalidates, renames old app to `previous.app` inside the work directory, renames candidate into the exact installed location, revalidates, then uses `/usr/bin/open -n <exact app> --args <fixed updater plan argument>` (argument arrays, no shell).
5. New main must **await** `registerStartup()` early and `acknowledgeStartup()` after backend AND window readiness. Admission remains closed until acknowledgement resolves. The latter publishes its PID-bound readiness receipt and waits for the helper's commit acknowledgement; `open` exit 0 alone is not success. Receipt publication is atomic no-replace, rejects persistent extra hard links, and never accepts incomplete JSON.
6. Before readiness commit, failure rolls back to the preserved old bundle. Only a boot-identified, not-yet-admitted new instance can receive SIGTERM; old analysis is never killed. If no trustworthy boot receipt exists, or the failed new instance cannot be confirmed stopped, preserve backup + lock and require manual recovery rather than guessing a PID. Old-bundle relaunch is attempted, but its `open` exit is not claimed as old-app readiness.
7. Readiness is the irreversible commit point: subsequent result-journal failure cannot kill new user work or roll back a ready app. Backups remain after success; there is no automatic backup deletion policy yet. `cancel()` after ready cancels the pending handoff; restart the service/app before another install attempt. `close()` after ready intentionally does not revoke an accepted handoff.

Power loss/forced termination between the two renames can leave the installed path absent while `previous.app` remains in the nonce work directory. No automatic crash recovery is claimed. Preserve that directory and lock, confirm both old/new processes stopped, then have a trusted operator verify/restore the backup; never delete a stale lock blindly. Same-user malicious modification and privileged administrator compromise are not isolated by POSIX file checks. Gatekeeper/quarantine may still require user approval; the updater never disables those controls.
