# Architecture — Stage 1 preserved, Stage 2–5 live path

React/TypeScript/Vite + React Flow; one Node/TypeScript exact-loopback HTTP server serves static assets and protected JSON APIs. There is no separate untrusted dev proxy.

## Independent paths

- **Demo:** `fixture.ts → git.ts → provider.ts MockProvider → contract.ts → main.tsx`. Actual fixture trees, explicitly simulated explanation/Jira. Other demo provider capability cards link conceptually to Live, not fake inference.
- **Live:** `github.ts / transport.ts → ingest.ts → live-git.ts → LocalStore → live.tsx`. `ingestPull` verifies identity, pins metadata, records API pagination/caps, fetches approved fixed objects, extracts actual DAG/tree/diffs, rechecks metadata races, and only then persists.
- **Optional sources:** `source-bridge.ts` adapts the standalone `jira/index.ts` module. Local settings and candidate edits are private persisted state. `captureForSnapshot` generates a new snapshot with normalized source references and preserved Jira raw/hash/time data. Nothing is fetched because a model mentions a URL.
- **Analysis:** `live-analysis.ts` builds bounded selected context, loads shipped runtime prompts and strict v2 schema, dynamically imports `ai/index.ts`, and verifies returned sources before persistence. Only explicit run POSTs invoke inference. `PRCE_AI_CONFIG` is server-owned configuration. Cached result metadata is supplied by the runtime, not generated by the model.

## Data and identity

`LiveSnapshot` explicitly models real PR metadata, connection/account/repository identity, fixed base/head/merge-base selection, each actual parent, actual trees, phase and net diffs, source/code evidence, optional Jira data and Coverage. It is not inferred from the fixture return type. The fixture retains its original compact `Snapshot` type for backwards-compatible tests.

Logical file identity is scoped by connection/account/repository; revision state has path/blob/mode/status/retrieval/rename evidence. Exact Git rename matches can preserve identity; non-exact matches are labeled uncertain and not merged. Not all ambiguous identical-blob rename cases are resolved. Parent diffs are never synthesized from adjacent display phases. Root phases use an explicit empty tree, multiple merge-bases produce no fabricated net comparison.

`LocalStore` uses stable hashed keys, private atomic JSON writes, bounded no-follow reads, retention and explicit deletion. SQLite was deliberately not introduced: this remains a single-user local application, not a multi-writer transactional job queue. JSON output caps mean large snapshots can fail safely instead of claiming full collection. Completed analyses persist, active jobs/session credentials do not survive restart.

## UI state / run state

`LiveApp` controls connection/list/workspace plus job progress and explicit provider/model/transmission consent. `LiveWorkspace` uses common snapshot/commit/comparison/file/side/range/mode/step/analysis URL state. Cached analysis key and per-snapshot read/continue state restore without re-running a model. `SourcePanel` is a narrow optional Jira interface.

Graph placement is based on stable file IDs. Static import edges, read-order tour steps, source issue references and model explanations are separate. Node/source selection cannot turn unsupported contents into retrieved code. Inferred-edge editing and a complete call graph are not implemented.

## Trusted integration seams

`LiveAPIOptions` accepts server/test-only factories (`client`, `ingest`, `execute`, `probe`), never request-provided executable paths/transports. Default implementations perform real work. Unit integration tests can inject labeled fixture transports/runners; production never silently switches to them.

AI: `probeProviders(config)` and `runAnalysis({providerId,model,schema,context,trustedPrompt,signal,onEvent,config})`. Jira: standalone discovery/manual/exclusion/batch-capture functions and Cloud/DC adapters. Ownership remains separate; core code does not modify either adapter directory.
